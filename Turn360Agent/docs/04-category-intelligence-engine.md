# 04 品类情报引擎 CategoryIntelligenceEngine

## 1. 模块目标

品类判断不能只靠“奶茶红海”“早餐刚需”这种粗判断。餐饮品类同时受消费属性、产品形态、地域、商圈、预算和用户能力影响。

本模块必须中立。红海品类不等于一定不能做，刚需品类也不等于一定能做。只要城市、地址、预算、用户能力和差异化证据成立，即使是奶茶、咖啡、烘焙，也可以输出“可做”；证据不成立时才输出高风险或不建议。

本模块负责：

- 品类分类
- 品类成本参数
- 地域适配
- 商圈适配
- 用户能力适配
- 选品建议

## 2. 品类三层分类

### 2.1 消费属性

| 类型 | 特点 | 示例 | 关键风险 |
|---|---|---|---|
| 刚需 | 高频、低决策、复购强 | 早餐、包子、面馆、盖饭、粉面、猪脚饭 | 辛苦、客单低、需要效率 |
| 轻社交 | 有情绪价值，单人也能买 | 奶茶、咖啡、甜品、烘焙、轻食 | 红海、品牌强、复购难 |
| 社交 | 多人、场景、空间依赖 | 火锅、烧烤、正餐、烤鱼、小酒馆 | 重资产、服务难、租金压力 |

### 2.2 产品形态

| 大类 | 子类 |
|---|---|
| 喝的 | 奶茶、咖啡、果汁、豆浆、酒饮 |
| 小吃 | 炸串、烤面筋、煎饼、葱油饼、卤味、臭豆腐 |
| 米面主食 | 盖饭、面馆、米粉、包子、饺子、粥 |
| 正餐 | 炒菜、火锅、烧烤、烤鱼、地方菜 |
| 烘焙甜品 | 面包、蛋糕、甜品、轻食 |
| 夜间品类 | 烧烤、夜宵、小酒馆 |

### 2.3 运营复杂度

| 复杂度 | 品类 | 适合人群 |
|---|---|---|
| 低 | 摆摊小吃、早餐单品 | 新手可尝试 |
| 中 | 快餐、面馆、卤味 | 有执行力的新手或轻经验者 |
| 高 | 奶茶、咖啡、烘焙 | 有运营和品牌意识者 |
| 很高 | 火锅、正餐、小酒馆 | 有管理经验和资金储备者 |

## 3. 地域影响因素

| 因素 | 影响 |
|---|---|
| 城市级别 | 县城更偏刚需与性价比，一线城市能承载更多轻社交和社交品类 |
| 气候 | 热区冷饮强，冷区热食、粉面、火锅更稳定 |
| 饮食口味 | 辣、面食、米饭、甜口、夜宵文化影响品类适配 |
| 收入水平 | 决定客单价上限 |
| 人群结构 | 学校、工厂、写字楼、小区、旅游区完全不同 |
| 外卖成熟度 | 决定是否能靠线上补流 |
| 本地强势品类 | 本地人已有强偏好时，新概念难教育 |

## 4. 数据源设计

### 4.1 官方宏观数据

用途：

- 城市消费能力
- 城乡消费差异
- 食品烟酒支出
- 人口与收入

来源：

- 国家统计局
- 中国统计年鉴
- 地方统计年鉴
- 商务部公开数据

### 4.2 行业数据

用途：

- 品类趋势
- 餐饮行业成本
- 行业增长与盈利情况

来源：

- 中国烹饪协会
- 中国饭店协会
- 美团指数
- 平台公开报告

### 4.3 位置与商户数据

用途：

- 区域同品类密度
- 大品牌分布
- 人均价格
- 评分和评论量
- 商圈活跃度

来源：

- 高德 POI
- 百度 Place API
- 腾讯位置服务
- 大众点评/美团开放或商业数据

### 4.4 自建数据

用途：

- 勇哥案例
- 用户诊断案例
- 失败原因标签
- 品类实际反馈

来源：

- `yongge-restaurant-skill/cases/`
- 用户授权上传的经营数据
- 后续人工标注

## 6. 品类适配评分

总分 100。

| 维度 | 分值 |
|---|---:|
| 用户能力适配 | 25 |
| 地址适配 | 25 |
| 地域适配 | 20 |
| 预算适配 | 15 |
| 竞争适配 | 15 |

### 6.1 用户能力适配

如果品类需要强运营，而用户能力低，直接红灯。

示例：

| 品类 | 最低能力分 |
|---|---:|
| 摆摊小吃 | 35 |
| 早餐 | 45 |
| 快餐 | 50 |
| 面馆 | 50 |
| 奶茶 | 70 |
| 咖啡 | 75 |
| 烘焙 | 75 |
| 火锅/正餐 | 70 |

### 6.2 地址适配

示例：

| 品类 | 好地址 |
|---|---|
| 早餐 | 学校、写字楼、小区通勤动线 |
| 快餐 | 写字楼、学校、工厂、社区 |
| 奶茶 | 年轻人密集、商业街、学校、商场 |
| 咖啡 | 写字楼、社区精品、商场 |
| 烧烤 | 夜间消费街、社区边缘、停车方便 |
| 火锅 | 聚餐目的地、停车、面积、排烟 |

## 7. 输出策略

### 7.1 不应该直接回答“做什么好”

应先问：

```text
你预算多少？
钱哪来的？
在哪个城市？
看好的铺位在哪？
你自己有没有餐饮经验？
你能不能每天守店？
```

### 7.2 输出格式

```text
适合做：
1. XXX，因为...
2. XXX，因为...

不适合做：
1. XXX，原因...

如果你非要做：
最低条件是...
保本日销大概是...
你需要具备...
```

## 8. QA 测试

### 8.1 新手想做奶茶

输入：

- 县城
- 预算 40 万
- 无经验
- 想加盟杂牌奶茶
- 附近有蜜雪

期望：

- 品类红灯
- 地址竞品红灯
- 用户能力不满足
- 明确不建议做，并说明是县城、无经验、杂牌、强竞品共同导致，不是因为“奶茶一定不能做”

### 8.2 新手低预算做小吃

输入：

- 预算 1 万
- 学校门口
- 做烤面筋/煎饼
- 能每天出摊

期望：

- 品类可尝试
- 提示先低成本验证
- 不建议租大店装修

### 8.3 小城市做咖啡

输入：

- 县城
- 预算 60 万
- 轻社交咖啡
- 用户无账号能力

期望：

- 品类高风险
- 要求证明客群和复购
- 若能力低则不建议做；若能补足客群证据和执行能力，可重新评估

### 8.4 地域规则测试

同一品类在不同城市和商圈下应输出不同结论：

- 一线写字楼咖啡：可分析
- 县城边缘咖啡：高风险
- 学校旁米饭快餐：可尝试
- 旅游景区山顶奶茶：高风险

### 8.5 正向支持测试

输入：

- 一线城市成熟写字楼
- 目标做咖啡
- 用户有 3 年咖啡店经验
- 地址 300 米内写字楼密集
- 租金占目标营业额低于 15%
- 周边竞品多但用户有明确差异化

期望：

- 不因“咖啡红海”默认劝退
- 输出可做条件
- 给开店前验证清单和保守日销目标
